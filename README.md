# WHITE BLANK — 白い地下迷宮

壁も床も天井も、すべて白い。光源はどこにもない。線も、縁取りも、模様もない。
それでも形が読めるのは、隅に落ちたわずかな陰りと、床や天井の厚みだけがあるからだ。

無限に広がる地下の迷路を、一人称で歩く。
やることはひとつ。世界にたったひとつだけある扉を見つけて、くぐること。

ブラウザだけで動く。ビルドも、素材ファイルもない。

## 遊びかた

```
python3 -m http.server 8080     # あるいは任意の静的サーバ
```
`http://localhost:8080` を開く。
（`file://` では ES モジュールが読めないので、必ずサーバ越しに）

| マウス | 見まわす（画面をクリックすると視点が固定される） |

## この世界のきまり

**世界は保存されない。** チャンクは、種と座標から必要になった分だけ計算し直される。
だから引き返せば、さっき通った通路がそのままそこにある。
遠ざかれば忘れられ、戻れば同じ形でまた組み上がる。無限に歩けるのはそのためだ。

**同じ種なら、同じ世界。** 種は覚えやすい名前で表示される。誰かと同じ迷宮を歩ける。

**上下にもつながっている。** 平面の迷路ではない。

- **階段** — 上下の部屋の形をそろえた、専用の階段室。
  横に道が要らないなら部屋いっぱいに広がり、左右はそのまま岩の壁になる。
  上りきった先には必ず踊り場が残る
- **斜路** — 段のない、ひと続きに傾いた坂。床にも壁にも平行でない面がひとつ混じるだけで、
  白い直方体の連なりが急に立体に見えはじめる
- **落下穴** — 床にあいた四角い穴。落ちたら、そこから登る道を別に探すことになる
- **吹き抜け** — 床そのものがない。上下の階がひと続きの空になっている

落下も吹き抜けも一方通行だ。だから「落ちた先に登る道がない窪地」を作らないよう、
生成のときに**歩いて往復できることを確かめている**（下の節を参照）。

**空間の寸法が、場所ごとに変わる。** 誰かが設計したように見えてほしい。

- 天井が突然かがむほど低くなり、その先だけ二階ぶんの高さで抜けている
- 壁いっぱいの開口と、人ひとり分の戸口が混ざる
- 角がときどき45度に落ちて、通路が斜めに曲がる
- **最大60mの巨大な縦穴**。粗い格子ひと目につき多くて一箇所だけ置かれる。
  その壁のあちこちの高さに通路の口が開いている。
  底から見上げれば道が見えるのに、そこへは直接行けない
- **裂け目と橋**。X方向に240mまで長く、Z方向は狭く、Y方向に80m近く深い溝。
  そこに橋が何本も架かっている。渡っていると腰までの欄干があって、
  越えられないが見わたせる。手の届かない高さと距離に、同じような橋がいくつも見える

**壁の印。** ところどころの壁に、誰が刻んだのかわからない記号がある。
位置も形も座標から決まっているので、道しるべになる。
足りなければ `E` で自分の印を刻める（種ごとにブラウザに残る）。

**音。** 足音は歩いた距離で刻まれ、空間の開けぐあいで残響の長さが変わる。
ときおり遠くで何かが崩れ、何かが軋む。姿は決して見えない。
扉が近づくと、その方向から低い唸りが聞こえはじめる。

## 誰かが掘った空間

通常の迷路をじゅうぶん歩いたあと、突然これに出くわす。
粗い格子ひと目につき多くて一つ、しかも周りの目より「強い」ときだけ置くので、
連続して現れることがない。目安としておよそ 500m にひとつ。

| | |
|---|---|
| **THE CATHEDRAL** | 白い柱の大広間。45〜60m四方、高さ16〜32m。同じ柱が延々と繰り返され、遠近がわからなくなる。一本だけ無い柱、一本だけ太い柱、途中で終わる柱、天井から垂れている柱が混ざる |
| **COMPRESSION** | 天井が下がり、幅が狭まっていく通路。抜けた瞬間に広間が開ける |
| **THE STAIR HALL** | 吹き抜けの壁づたいに、いくつもの階段。渡れるのは一本だけで、残りは「そこにあるのに、どうやって行くのか分からない」 |
| **STACKED CORRIDORS** | 縦長の空洞のまわりを、各階の回廊が取り巻く。少し前に歩いた道を、別の高さから見ることになる |
| **NESTED ROOM** | 巨大な部屋の中に、巨大な箱。その中にも空間がある。開口の位置は層ごとにずれていて、外から内へ入ったあと、別の方向から外へ出る |
| **THE DESCENT** | 中央の吹き抜けを囲んで、階段が何階ぶんも降りていく。24〜43m。見上げれば、入ってきた口がはるか上に見える |

設計思想は固定し、寸法・柱の間隔・欠損・出入口・高低差だけを種で動かしている。
色も装飾も使わない。違いはすべて、大きさ・比率・陰影・遮蔽・反復・見通しだけで出す。

ランドマークは大空間（縦穴・裂け目）より優先され、同じ場所で競合しない。
出入口は必ず2つ以上あり、**入って、渡って、帰ってこられる**ことを毎回検証している。

開発中は URL に `?landmark=cathedral` のように付けると、その場所へ直接立てる
（`cathedral` / `compression` / `stairs` / `stacked` / `nested` / `descent`）。

### さらに100種類の探索空間

既存6種類を残し、`LM_001`〜`LM_100`を追加。
門、天井、岩の塊、部屋、経路、縦空間、登れる回廊、足元の違和感、視点の錯覚、巨大な象徴の10系統。
100個の異なる空洞構成を持ち、common 38 / uncommon 34 / rare 18 / very rare 10種類。
色ではなく、見通し・遮蔽・輪郭・内部構造で見分ける。

入口の向こうの変な形へ近づき、回り込むと別の空間が見つかる。
14種類には登れる上段があり、巨大なものは近づいた場所だけ遠くまで読み込んで見通せる。
通常迷路の読み込み範囲は変えず、離れた空間の描画・衝突は解放する。

[全100種類の設計・寸法・rarity・生成規則](docs/landmarks-100.md)。
[検証結果と全100種類の入口画像](docs/landmark-verification.md)。
開発用URLは `?landmark=LM_001` など。希少な種類の検索には時間がかかる場合がある。
`npm run build` で検査済みの静的配布物を `dist/` に生成する。

追加検証: `npm test` / `npm run test:landmarks` / `npm run test:geometry` / `npm run test:browser`。
`node tools/legacy-landmarks.mjs` で元コミットの6種類の配置と形状を比較できる。

### 壁を立てるのではなく、岩を彫る

この世界に「壁」という部品はない。あるのは岩の塊と、そこに彫られた空洞だけだ。

空洞は**箱の合併**でできている。

- **部屋の箱** — セルの中に、まわりに岩を残して彫った直方体
- **喉の箱** — 隣の部屋とのあいだの岩を貫く通り道
- **縦穴の箱** — 床と天井の板を貫く穴

貼るのは「箱の面のうち、他の箱に塞がれていない部分」だけ。
箱どうしは面でぴったり接するので、こうして得た面は必ず閉じている。
薄板のような壁が宙で切れる、ということが原理的に起こらない。

部屋はセルの境界から必ず 0.5m 内側に引っこむので、
隣り合う空洞のあいだには必ず岩の厚みがある。
戸口をくぐるとき、その厚みが目に見える。

部屋の広さは3セル角のかたまりごとに決まる。
だから通路は何セルか同じ幅で続き、かたまりの境で変わる。
**幅が変わるところが、そのまま戸口になる。** 戸口を「置いて」いるわけではない。

### 無限なのに、ちゃんとつながっている理由

局所的な規則だけで「どこへでも歩いて行ける」を保証している。

1. チャンク内はひとつながりの空洞だけ残して全域木で掘る
2. 隣り合うチャンクの境界面には必ず出入口を開ける。
   面を共有する2つのうち座標の小さい方を基準に乱数を引くので、
   両側が独立に計算しても寸分たがわず同じ位置に穴が開く
3. 落下は一方通行なので、**立てる床のあるセルだけを点**とし、
   往復できる辺——水平の通路と階段——だけで連結成分を数え、
   ばらけている間だけ落下穴を階段に書き換える

床のない縦つなぎ（吹き抜け）を迷路の骨格に使うと、その下端が
「落ちて入るだけの袋小路」になる。骨格からは外し、景色としてだけ足している。

`tools/reach.mjs` が、この性質を毎回たしかめている。
「行ける場所の集合」と「帰ってこられる場所の集合」を両方向から塗って、一致するかを見る。

### つながっていても、通れるとは限らない

リンクがあることと、人が通れることは別の話だ。

- 天井 1.94m の部屋に高さ 1.66m の戸口を切ると、背丈 1.74m は通れない
- 階段が上の部屋の床を丸ごと飲み込むと、上りきった先に立つ場所がない
- 喉の床はセルの境をまたぐので、当たり判定を「作ったセル」だけに登録すると、
  その半分が抜けて床をすり抜けて落ちていく

`tools/gaps.mjs` が、すべての通路について通れる寸法が残っているかを数えている。

### 試験

```
npm install          # three と playwright（同梱のChromiumを使う）
node tools/reach.mjs # 行った先から必ず帰ってこられるかを確かめる（ブラウザ不要）
node tools/gaps.mjs  # どの通路にも人が通れる寸法が残っているか（ブラウザ不要）
node tools/check.mjs # 登る・落ちる・刻む・くぐる・沈まないを実際に確かめる
node tools/shot.mjs  # 実際に歩いて shots/ に絵を残す
```

`check.mjs` は描画を待たずに世界の時間だけを進めるので、
機械の速さに関係なく同じ結果になる。


### スマートフォンの操作

タッチ主体の端末では、開始後に仮想スティックとタッチボタンを表示します。
左側で触れた位置を基準に、スティックを倒した方向へ前後左右に移動します。
前へ大きく倒すとダッシュし、右半分のドラッグで上下左右の視線を調整できます。
左右は同時に使えます。「跳ぶ」「印」「中断」ボタンもあります。
指を離す・タッチをキャンセルする・画面を回転する・中断する際には入力を解除します。
PCでは従来のキーボードとマウス操作を維持します。

`npm run test:touch` はChromeのマルチタッチ入力で操作、物理加速、入力解除、縦横画面、PC表示を検査します。
必要なら `WB_CHROME` にChromeの実行ファイルを指定してください。スマホ実機のFPS検証は未実施です。
